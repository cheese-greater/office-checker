# Office Lock Checker

A small Windows app that shows who has Office documents locked. Drop documents or folders on it and it decodes the
Office lock files (`~$...`) beside each document to show the user name and Windows account that opened it.

The window is drawn in the Windows XP Luna (blue) style. `XpForm` paints the title bar and frame itself while
Windows still handles move, resize, snap and maximize; the `Xp*` controls and `XpTheme` cover the rest. The caption
buttons are the original XP bitmaps as traced by [XP.css](https://github.com/botoxparty/XP.css) (MIT license);
`assets\Convert-XpCaptionButtons.ps1` regenerates `assets\caption\*.png` from its stylesheet.

## Use

Run `bin\OfficeLockChecker.exe`, then do any of the following:

- Drag files, several files, or folders onto the window.
- Drag them onto the exe icon in Explorer (or onto a shortcut to it).
- Use Choose Files or Choose Folder.

Other controls:

- **Include subfolders:** checks dropped folders recursively.
- **Hide unlocked documents:** filters the list to documents that need attention.
- **Refresh (F5):** checks the same items again. Escape stops a long check.
- **Right-click a row:** opens its folder or copies rows as tab-separated text that pastes into Excel.

| Status | Meaning |
| --- | --- |
| Locked | The document is open and its lock file names who opened it. |
| In use, no lock file | The document is held open but there is no lock file, so the user is unknown. |
| Possibly stale lock | A lock file exists but the document is not open, usually left over from a crash. |
| Orphan lock file | A lock file whose document is gone (renamed, moved or deleted). |
| Not locked | No lock file and the document is not open. |

The app needs only the .NET Framework 4.8 that ships with Windows 10 and 11, so the exe can be copied anywhere.

## Build

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

This compiles `src\*.cs` with the `csc.exe` that ships with the .NET Framework (C# 5, so no newer language features)
and writes `bin\OfficeLockChecker.exe`. The icon is generated by `assets\New-AppIcon.ps1` if `assets\app.ico` is missing.

## How it works

- **Lock file names:** Excel and PowerPoint name the lock `~$` plus the full file name; Word replaces up to the first two
  characters (`Project Plan.docx` becomes `~$oject Plan.docx`). LibreOffice uses `.~lock.<name>#`.
- **Lock file contents:** byte 0 holds the user name length and the ANSI name follows. A UTF-16 copy follows a 16-bit
  length at byte 54 (Word, 162 bytes) or byte 55 (Excel, 165 bytes). LibreOffice locks are comma-separated text.
- **Open check:** the app briefly opens each document while denying other writers. That fails while Office has the file
  open, including over SMB from another machine, which is what separates Locked from Possibly stale.
- **Windows account:** the owner of the lock file on disk, which is the account that created it.
- **Cloud placeholders:** OneDrive cloud-only files are not opened, so checking never triggers a download.

## Limits

- The user name is the Office "User name" setting (File > Options > General), which people can set to anything. The
  Windows account column is the more reliable identity.
- Documents co-authored through OneDrive or SharePoint may not hold the local file open, so a live session can show as
  Possibly stale.
- Some NAS shares do not enforce Windows share modes; there an open document can also show as Possibly stale.
- The exe is unsigned, so SmartScreen may warn the first time it runs from a downloaded or network location.
